# Extruder Parameter Predictor

> هسته‌ی تمایز محصول: مدل ML که ترکیب ورودی (خروجی [[entities/polymer-identification]]) را
> مستقیماً به دما، سرعت و فشار بهینه‌ی اکسترودر نگاشت می‌کند.

## مسئولیت‌ها
- دریافت ترکیب/خلوص پلیمر ورودی به‌عنوان feature
- پیش‌بینی تنظیمات بهینه‌ی اکسترودر برای کمترین نرخ رد کالا
- ارائه‌ی پیشنهاد به اپراتور از طریق داشبورد (issue #9)

## وابستگی‌ها
- [[entities/polymer-identification]] — منبع داده‌ی ورودی مدل
- [[entities/feedback-loop]] — بازآموزی مدل بر اساس نتیجه‌ی واقعی هر بچ
- [[concepts/data-moat]] — دقت این مدل مستقیماً وابسته به حجم داده‌ی بومی جمع‌آوری‌شده است

## قراردادها / Edge cases
- مسئله‌ی بهینه‌سازی چندمتغیره است — انسان با آزمون‌وخطا حلش می‌کند، این مدل باید آن را
  پیش‌بینی کند (نه صرفاً classification ساده).
- KPI ارزیابی مدل مستقیماً به نرخ رد کالا (target: زیر ۵٪) گره خورده، نه فقط accuracy آماری.

## وضعیت
نسخه‌ی آزمایشی historical-neighbor پیاده‌سازی شده است، نه مدل صنعتی بهینه‌سازی. از [[concepts/production-workflow]] خلوص/رطوبت، دستگاه و پلیمر اصلی را می‌گیرد. حداقل ۸ بچ تأییدکیفی‌شده با نرخ رد کمتر از ۵٪ برای همان کارخانه/دستگاه/پلیمر لازم است. میانگین تنظیمات ۳ همسایه‌ی نزدیک پیشنهاد می‌شود؛ خارج از دامنه‌ی ثبت‌شده یا حدود دستگاه پیشنهاد صادر نمی‌شود.

نسخه با fingerprint داده و الگوریتم ذخیره می‌شود؛ ارزیابی داخلی MAE روی holdout زمانی حداقل ۲نمونه‌ای است و تضمین نرخ رد نیست. ورودی/خروجی/ارزیابی در DB ذخیره می‌شوند. تأیید صریح اپراتور با هویت/زمان لازم است؛ تغییر داده‌ی واجد شرایط مانع تأیید پیشنهاد قدیمی می‌شود. هیچ اتصال به دستگاه یا کنترل PLC وجود ندارد. هیچ مدل با داده‌ی واقعی کارخانه در این اجرا آموزش یا اعتبارسنجی نشده است.

GitHub issues #6/#8/#9 پیش رفته‌اند؛ آموزش صنعتی و پایلوت هنوز باز هستند. [[entities/polymer-identification]] هنوز منبع خودکار ورودی نیست؛ ورود فعلی دستی/CSV است.
