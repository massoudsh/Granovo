# Schema — قوانین ویکی دانش پروژه (Granovo)

> این ویکی طبق «Vault Recipe» ساخته شده: خلاصه‌ی زنده و append-friendly از entity ها و
> concept های پروژه، به‌جای re-scan کردن کل کدبیس در هر مکالمه.

## ساختار پوشه
```
docs/wiki/
  schema.md      # همین فایل
  overview.md    # یک‌نگاه کلی پروژه (≤۴۰۰ کلمه)
  index.md       # کاتالوگ همه صفحات، گروه‌بندی‌شده
  log.md         # تاریخچه append-only (جدیدترین در پایین)
  entities/      # هر entity مهم یک صفحه (مدل داده، سرویس، ماژول کلیدی)
  concepts/      # patternها، flowها، تصمیم‌های معماری
  sources/       # (اختیاری) خلاصه فایل‌های خام که چندجا ارجاع داده می‌شوند
```

## شروع هر مکالمه/سشن
1. اول `overview.md` و `index.md` را بخوان. هرگز کل کدبیس را re-scan نکن.
2. فقط صفحات مرتبط با تسک فعلی را drill-down کن.
3. اگر صفحه‌ای وجود نداشت، آن را طبق همین قواعد بساز.

## وقتی کد را تغییر دادی — قانون اکید
هر بار یک فایل پروژه تغییر کرد (خارج از `docs/wiki/` خودش):
1. تشخیص بده این تغییر روی کدام entity/concept اثر می‌گذارد.
2. صفحه‌ی مربوطه را به‌روز کن (فیلد جدید/حذف‌شده، امضای تابع، route جدید، dependency جدید، edge case).
3. اگر entity/concept کاملاً جدید و به‌اندازه‌ی کافی مهم است، صفحه‌ی جدید بساز و در `index.md` لینک بده.
4. یک خط در `log.md` اضافه کن: `## [YYYY-MM-DD] update | <خلاصه تغییر>`.

تغییرات trivial (typo، فرمت) نیاز به آپدیت ندارند. اگر چند فایل در یک مکالمه تغییر کردند،
آپدیت‌های ویکی را یک‌بار در پایان انجام بده، نه بعد از هر فایل.

## چه وقت صفحه‌ی جدید بساز
- فقط اگر ≥۳ جای دیگر قرار است به آن لینک بدهند، یا concept مستقلی با حجم قابل‌توجه است.
- در ۹۰٪ موارد به‌جای فایل جدید، صفحه‌ی موجود را آپدیت کن.
- هرگز صفحه‌ی trivial نساز.

## ساختار صفحه‌ی entity
```markdown
# {نام}

> یک‌خطی توضیح هدف.

## مسئولیت‌ها
- ...

## وابستگی‌ها
- [[concepts/xxx]] — چرا
- [[entities/yyy]] — چطور

## قراردادها / Edge cases
- ...

## منابع کد
- `path/to/file.ts:42` — کلاس اصلی
```

## قواعد لینک (Obsidian-style)
- `[[entities/user]]` بدون پسوند `.md`.
- نام فایل: lowercase + hyphen.
- wikilinkهای نمونه داخل بک‌تیک/code block لینک واقعی محسوب نمی‌شوند.

## Lint دوره‌ای
وقتی خواسته شد «ویکی رو بازبینی کن»:
1. orphan pages — لینک بده یا حذف کن.
2. broken link — صفحه‌ی گمشده را بساز یا لینک را حذف کن.
3. تناقض بین صفحات — بهترین حدس را انتخاب کن و در log ثبت کن.
4. صفحات کهنه — بازخوانی و sync.
